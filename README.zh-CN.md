# 短信转发 SmsForwarder

**手机收到的每一条短信，实时转发到你的邮箱，一封一条。**

原生 Android 应用（Kotlin），把收到的短信逐条转成邮件，主题与正文完整。为「手机不能带在身边」的场景而做——比如在校：把手机留在家里，上课期间在邮箱里看验证码。

典型用法：用 **126 邮箱**作为收件箱——126 网页端登录无需二次短信验证码，在校打开网页邮箱就能取到刚到的验证码。

## 工作原理

```
手机收到短信 ──► SmsReceiver（广播，实时）──┐
                    ReconcileWorker（补偿，每 15 分钟 / 打开应用 / 手动扫描）
                                            ├─► Room 数据库 ─► SendQueueWorker ─► SMTP ─► 你的邮箱
```

两条独立链路喂给发送队列：

- **实时链路**：系统 `SMS_RECEIVED` 广播到达即处理（应用在前台或被保活时秒级转发）。
- **补偿链路**：每 15 分钟扫描 + 打开应用时扫描 + **立即扫描**按钮，回捞近 30 分钟短信——即使进程被杀也**不丢短信**。

## 功能特性

- **一封一条**：每条短信一封邮件，主题如 `[短信转发][卡1·中国移动] 138****1234 · 10-24 09:30`（可在设置中打开完整号码），正文含短信全文、接收时间、卡槽、8 位消息 ID。
- **实时转发**：广播接收器 + 前台保活服务；MIUI/HyperOS 按应用内引导完成保活（自启动、无限制、任务加锁）后接近系统级常驻。
- **绝不丢短信**：打开应用 / 每 15 分钟 / 手动「立即扫描」回捞近 30 分钟短信；按消息键幂等，不会重复发。
- **长短信自动拼接**：多片长短信（超长验证码）拼接为完整正文再发送。
- **双卡识别**：通过 `SubscriptionManager` 实时识别卡槽与运营商；某些 ROM 无卡槽列时优雅降级为「未知卡槽」。
- **邮箱预设**：126 / 163 / QQ / Gmail / Outlook / iCloud 等一键填充（服务器、端口、加密），支持自定义 SMTP。
- **自动开网络（可选，默认关）**：短信到达时若没有可用网络，自动打开 WiFi；**连不上 WiFi 时再开移动数据**，发送完成后恢复原状。详见下文。
- **网络失败长期补发**：断网 / SMTP 连不上时标记为「网络失败」并长期等待，网络恢复后自动补发，不占用 5 次重试上限。
- **可靠投递**：串行队列、至少一次语义、崩溃恢复、指数退避（最多 5 次）、失败分类（鉴权 / 地址 / 5xx 与网络 / 超时 / 4xx 区别对待）。
- **隐私优先**：发件号码默认打码（`138****1234`），需要时再打开完整号码；SMTP 授权码用 AES-256（EncryptedSharedPreferences）加密存储，`allowBackup=false`。
- **干跑模式（默认关闭）**：开启后本地照常监听、解析、入库但不真实发送；装好用即真实转发。
- **Shizuku 守护（v1.3.2，随自动开网开关启用）**：每 5 分钟检测，把 `shizuku_server` 固定为系统「不可杀」级别（`oom_score_adj = -1000`），后台清理（MIUI/HyperOS）不再回收；Shizuku 停止时发常驻通知提醒。
- **关于页**：设置 → 关于，可查看版本号与离线内置的中英文说明。

## 快速开始（3 步）

1. **安装并授权**：打开应用 → 设置 → 打开「启用短信转发」→ 保存，授予所需权限（接收短信 / 读取短信 / 手机状态 / 通知）。
2. **配置邮箱**：选择 126 预设，填入 126 邮箱地址和 **SMTP 授权码**（不是登录密码），点「发送测试邮件」验证链路，再关闭「干跑模式」。
3. **MIUI 保活**：打开应用内「小米保活设置引导」，完成核心 3 项：**允许自启动、电池无限制、最近任务加锁**。

### 获取 126 邮箱 SMTP 授权码

1. 电脑浏览器登录 https://mail.126.com ；
2. **设置 → POP3/SMTP/IMAP** → 开启 **SMTP 服务**（安全提示点继续）；
3. 生成一串 16 位左右的**授权码**，复制到应用里——应用用它发信，不是登录密码。

> 任何支持 SMTP 的邮箱都可用。126/163/QQ 用 16 位授权码；Gmail/Outlook 用应用专用密码。

## 短信到达时自动开启网络（可选）

设置页打开「短信到达时自动开启网络（发送后关闭）」，**默认关闭**。策略：

- 发送前优先自动开 **WiFi**；**WiFi 连不上 / 没有可用网络时才开移动数据**（有 WiFi 时不动数据，省流量）；
- 发送完成后**恢复原状**——只关掉本功能临时打开的开关，你本来就开着的网络不会被关闭。

**系统限制（重要）**：Android 11+ 禁止第三方应用直接开关 WiFi / 移动数据（`setWifiEnabled` 对第三方一律失效，移动数据无公开 API）。本应用通过 **Shizuku**（无 Root）在一次 adb 授权后获得 shell 能力执行 `svc wifi/data enable`。

**v1.3.0 起内置 Shizuku 官方安装包，无需联网下载**：打开开关时自动检测——未安装会弹窗并可一键安装应用内置的 Shizuku（首次会请求「允许安装未知应用」），已装未激活会给出激活步骤。

1. 打开「自动开网络」开关 → 弹窗点「去安装」→ 允许安装 → 继续，Shizuku 即装好；
2. 手机开启 **开发者选项 → USB 调试**，连接电脑；
3. 电脑执行激活命令（Shizuku 13.6 起为安装目录下的 `libshizuku.so`，**路径随安装实例变化**；应用弹窗会自动读取并显示真实路径，也可在 Shizuku 应用内点「查看指令」获取）：
   ```
   adb shell <Shizuku 安装目录>/lib/arm64/libshizuku.so
   ```
   例（每次安装路径可能不同，以弹窗显示为准）：
   ```
   adb shell /data/app/~~XXXX==/moe.shizuku.privileged.api-XXXX==/lib/arm64/libshizuku.so
   ```
4. 打开 Shizuku 应用，点击启动，在「已授权的应用」中允许「短信转发」；
5. 设置页开关保持打开即可。（adb 模式在重启手机后失效，重启后需重新执行一次激活命令。）

> 注：旧版 Shizuku 文档里的 `adb shell sh /sdcard/Android/data/.../start.sh` 在 13.6 已废弃，会报 No such file。

未激活 Shizuku（也无 Root）时该功能无法自动开网；此时**网络失败会长期标记等待，网络恢复后自动补发**，不会丢短信。

### Shizuku 守护（v1.3.2，防 Shizuku 被杀）

部分系统（尤其 MIUI/HyperOS）的后台清理会把 Shizuku 进程回收，导致自动开网失效。**v1.3.2 内置 Shizuku 守护**：

- 打开「自动开网络」开关后自动启用，每 5 分钟检测一次；
- Shizuku 运行时，通过 Shizuku 的 shell 能力把 `shizuku_server` 的 `oom_score_adj` 写为 `-1000`（系统"不可杀"级别），**LMKD 不再回收它**（实测有效且不被回改）；
- pid 动态获取（`pidof shizuku_server`），**无需判断安装路径，全机型通用**；
- 若 Shizuku 已完全停止（如重启手机后未重新激活），守护无法自行重启它（启动脚本必须以 adb/shell 身份执行，Shizuku 停止时应用拿不到 shell 通道），此时会发出**常驻通知**提醒重新激活，恢复后通知自动消失。

配合下方 MIUI 保活 3 项，Shizuku 可长期常驻，自动开网功能持续可用。

## MIUI / HyperOS 保活（核心 3 项，务必完成）

> **两个应用都要做**：①「短信转发」（转发本身）；②「Shizuku」（自动开网依赖）。
> 实测（v1.3.2）：Shizuku 的应用进程一旦被清理，`shizuku_server` 会随之退出，自动开网即失效——
> 所以 **Shizuku 的保活比短信转发更关键**。尤其不要在最近任务里手动滑掉 Shizuku。

| # | 设置项 | 路径 |
|---|---|---|
| 1 | **允许自启动** | 设置 → 应用设置 → 授权管理 → 自启动管理 → 允许「短信转发」与「Shizuku」 |
| 2 | **电池无限制** | 设置 → 应用管理 → 短信转发 / Shizuku → 电池省电策略 → **无限制** |
| 3 | **最近任务加锁** | 多任务界面下拉「短信转发」与「Shizuku」卡片，出现锁形图标 |

再打开通知权限（前台服务依赖），并保持 WLAN 休眠时连接。应用内引导列出了完整步骤。

> 为什么做不到微信那种「强停后仍能收」：微信是预装系统应用，有厂商推送通道，消息由系统推送服务送达、不依赖应用进程；第三方应用无法加入该通道。本应用的替代方案是**两层**：前台保活让进程尽量不被杀，补偿扫描保证被杀也不丢短信（最迟 15 分钟后、或下次打开应用时发出）。任何应用在被系统「强制停止」后都无法被广播唤醒，重新打开一次即可。

## 常见问题

**没有收到转发邮件？** 确认转发已启用、干跑已关闭、授权码正确（可在 126 网页端重新生成）；看状态页：`失败(永久)` 多为配置/凭据问题（改完点「重试失败」），`失败(重试N)` 为临时网络问题（自动重试）；再检查垃圾邮件，部分邮箱会把「自发自收」判为垃圾。

**重复邮件？** 极少（仅在邮件已发出但手机没收到确认时）；正文里的 8 位消息 ID 可识别重复，这是「至少一次」语义的必要代价。

**发出的短信不转发？** 设计如此：仅转发**收到**的短信。

**「未知卡槽」？** 部分 ROM 不暴露短信视图的卡槽列，属正常降级，不影响转发。

**长短信？** 多片正文会拼接成一封；极端乱序可能标记为「不完整」，仍按收到内容发送。
