# SmsForwarder
**手机收到的每条短信，分条实时转发到你的邮箱。**

原生 Android 应用（Kotlin），把收到的短信逐条发到指定邮箱：一条短信一封邮件，主题、正文都带上。
为"不能带手机"的场景设计——比如学校：手机放家里，课间打开邮箱就能看到刚收到的验证码。

典型搭配是 **126 邮箱**作为接收端：126 网页邮箱登录不需要短信验证码，在学校用电脑/平板开网页
邮箱，就能拿到转发进来的验证码。

## 工作原理

```
手机收到短信 ──► SmsReceiver（广播，实时）──────┐
                    ReconcileWorker（补偿，       ├─► 本地库 ─► SendQueueWorker ─► SMTP ─► 你的邮箱
                    每15分钟/打开应用/            │        （至少一次，自动重试）
                    手动"立即扫描"）──────────────┘
```

两条独立通道向发送队列喂数据：
- **实时通道** —— 短信到达瞬间处理系统 `SMS_RECEIVED` 广播（应用在运行、或进程被保活时生效）。
- **补偿通道** —— 每 15 分钟的周期扫描 + 状态页"立即扫描短信"按钮，重新比对系统短信库，
  把最近 30 分钟内错过的短信全部捞回，**短信一条都不会丢**（即使进程被杀）。

## 功能

- **一条短信一封邮件** —— 主题如 `[短信][卡1·中国移动] 138****1234 · 10-24 09:30`
  （可改为显示完整号码），正文含完整内容 + 接收时间 + 卡槽 + 8 位消息 ID。
- **实时转发** —— 广播接收器 + 前台保活服务；在 MIUI/HyperOS 上按应用内引导完成设置
  （自启动、电池无限制、任务加锁），表现接近系统应用。
- **一条不丢** —— 补偿扫描：打开应用、每 15 分钟、或手动点"立即扫描短信"，
  最近 30 分钟内的短信都会补发；按短信唯一键去重，**不会产生重复邮件**。
- **长短信合并** —— 超过 70 字被拆分的长短信（验证码常见），自动拼回完整正文再发。
- **双卡自动识别** —— 实时读取 `SubscriptionManager` 判断卡槽与运营商；
  系统短信库没有卡槽字段时优雅降级为"未知卡槽"。
- **主流邮箱预设** —— 126 / 163 / QQ / Gmail / Outlook / iCloud 等一键填好
  （服务器、端口、SSL），也支持自定义 SMTP。
- **干跑模式（默认开启）** —— 一切流程本地走完，但**绝不真正发信**；确认无误后再关闭。
- **可靠投递** —— 串行发送、至少一次语义、崩溃恢复、指数退避重试（最多 5 次）、
  永久失败分类（鉴权/地址/5xx 与 网络/超时/4xx）、每轮 9 分钟硬时限 + 链式续投。
- **默认保护隐私** —— 号码默认脱敏 `138****1234`（可开完整号码）；SMTP 授权码用
  AES-256 加密存储（EncryptedSharedPreferences），不明文落盘，`allowBackup=false`。
- **MIUI 引导页** —— 应用内逐步引导 MIUI / HyperOS 保活设置。

## 快速开始（3 步）

1. **安装并授权**。打开应用 → **设置** → 打开"转发已启用"→ 保存。
   允许所有请求的权限（接收短信 / 读取短信 / 手机状态 / 通知）。
2. **配置邮箱**。选 **126 邮箱**预设，填 126 地址和 **SMTP 授权码**（不是登录密码），
   保持**干跑**开着点"发送测试邮件"验证整条链路（不会真发信），确认后关闭干跑。
3. **保活（MIUI）**。打开应用内**小米保活设置引导**，完成核心 3 项：
   **允许自启动**、**电池策略无限制**、**最近任务加锁**。

### 获取 126 邮箱 SMTP 授权码

1. 电脑浏览器登录 https://mail.126.com；
2. **设置 → POP3/SMTP/IMAP** → 开启 **SMTP 服务**（出现安全提示，点继续）；
3. 页面会生成一次性 **授权码**（一串随机字符），复制进应用即可——发信用的是它，不是登录密码。

> 任何支持 SMTP 的邮箱都可以：126/163/QQ 是 16 位授权码，Gmail/Outlook 用应用专用密码。
> 如果接收邮箱的网页登录本身需要二次验证，在学校收转发邮件时就要带上那个条件。

## 学校场景（收验证码）

1. 手机（运行着本应用）放家里——电池无限制 + 自启动 + 任务加锁；
2. 在学校需要验证码时，任何地方点"获取验证码"（登录页、支付等）；
3. 手机几秒内把验证码转发到你的 126 邮箱；
4. 在学校电脑/平板打开网页邮箱——**126 网页登录不需要短信验证码**，拿到验证码完成登录。

## MIUI / HyperOS 保活（核心 3 项，全部要做）

| 序号 | 设置 | 路径 |
|---|---|---|
| 1 | **允许自启动** | 设置 → 应用设置 → 授权管理 → 自启动管理 → 允许本应用 |
| 2 | **电池策略：无限制** | 设置 → 应用管理 → 短信转发 → 电池省电策略 → **无限制**（弹窗选"允许后台活动"） |
| 3 | **最近任务加锁** | 多任务界面 → 下拉应用卡片 → 出现锁形图标 |

随后开启**通知**（前台保活依赖）、WLAN 休眠保持连接。应用内引导页列有完整清单。

> 为什么做不到微信那种"被强制停止还能收到消息"：微信是系统预装应用并接入**厂商推送通道**——
> 消息由系统推送服务送达，不依赖应用进程存活；第三方应用无法接入该通道。本应用提供的替代是
> **两层保险**：前台保活让进程几乎不被杀；补偿扫描保证即使进程被清理，短信也不丢——邮件最多
> 延迟 15 分钟发出（或下次打开应用/点"立即扫描"立刻补发）。
> 唯一无法绕过的是系统「**强制停止**」后广播无法唤起进程，需要手动打开一次应用（所有应用都如此，
> 微信也不例外）。

## 常见问题

**收不到转发邮件？** 检查：转发已启用、干跑已关闭、授权码正确（126 网页端重新生成）；
看状态页——`失败(永久)` = 授权码/配置问题（改完点"重试失败"），`失败(重试N次)` = 网络临时问题
（自动重试）；再查手机网络和邮箱垃圾箱（部分邮箱会把"自发自收"判为垃圾邮件）。

**收到重复邮件？** 极少数网络异常下可能重发（邮件已发出但手机没收到确认），正文的 8 位
"消息 ID"可用于识别；这是"至少一次"语义下无法 100% 避免的，属正常现象。

**已发送的短信不转发？** 设计如此：只转发**收到**的短信，不转发自己发出的。

**显示"未知卡槽"？** 部分机型系统短信库不含卡槽字段，属正常降级，不影响转发。

**长短信？** 分片自动合并为完整正文再发；个别极端乱序会标记"分片不完整"，正文以收到内容为准。
